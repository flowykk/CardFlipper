# Массовое назначение тегов словам

## Цель

Позволить добавить один или несколько существующих тегов сразу к нескольким словам из библиотеки, не открывая редактор каждой карточки. Уже назначенные карточкам теги всегда сохраняются.

## Пользовательский сценарий

1. Пользователь открывает библиотеку и при необходимости использует поиск или фильтры тегов, чтобы сузить список.
2. Нажимает явную кнопку выбора в панели библиотеки.
3. Экран переходит в режим массового выбора: у строк появляются чекбоксы, а в нижней панели отображаются число выбранных слов и действие «Теги».
4. Пользователь отмечает одну или несколько карточек, затем открывает выбор тегов.
5. В модальном экране отмечает один или несколько тегов и подтверждает «Добавить к N словам».
6. Приложение добавляет отсутствующие выбранные теги к каждой выбранной карточке, сохраняет изменения и возвращает обновлённый список. Дубли тега у одной карточки не создаются.

## UX-решение

Вход — отдельная, доступная кнопка выбора, а не долгое нажатие на тег. Это действие заметнее, не конфликтует с текущим контекстным меню удаления тегов и естественно поддерживает добавление нескольких тегов сразу.

Поиск и фильтры продолжают работать в режиме выбора: они определяют, какие карточки видны, но не сбрасывают уже отмеченные карточки. Пользователь может отменить режим без изменений. После успешного назначения режим завершается, а выбор очищается.

## Компоненты и границы

- `LibraryView` управляет представлением: кнопкой входа, отображением чекбоксов, нижней панелью и листом выбора тегов.
- `LibraryViewModel` хранит состояние массового режима, идентификаторы выбранных карточек и выполняет операцию добавления тегов.
- `CardRepository` получает операцию массового обновления карточек либо сохраняет обновлённые карточки через существующий `save` в одном выделенном методе view model.
- Репозиторий SwiftData сохраняет изменения надёжно: ошибка не меняет локальное состояние списка до успешного сохранения. При ошибке пользователь видит повтор действия или отмену.

## Данные и правила

- Набор новых тегов объединяется с текущими тегами каждой карточки по `Tag.id`.
- Карточки, где все выбранные теги уже есть, остаются без смысловых изменений.
- Нельзя подтвердить действие без выбранных карточек или тегов.
- Порядок карточек и существующее поведение поиска, фильтрации и удаления не меняются.

## Доступность

- Кнопка входа, чекбоксы, счётчик и подтверждение получают понятные accessibility labels и identifiers для UI-тестов.
- Чекбокс сообщает выбранное состояние стандартным accessibility trait.
- Действия отмены и подтверждения доступны из нижней панели и модального выбора тегов.

## Проверка

- Unit-тесты view model: выбор/снятие выбора, объединение тегов без дубликатов, сохранение прежних тегов, успешное обновление и обработка ошибки.
- UI-тест: отфильтровать список, выбрать несколько слов, добавить тег и убедиться, что тег отображается в карточках после перезагрузки.
